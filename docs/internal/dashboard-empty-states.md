# 仪表盘与图表空状态

`/dashboard` 是唯一使用 `web/src/components/dashboard/metric-chart.tsx` 的页面。这里的约定是 INT-151 定下的：空数据时不要把「没有数据」画成一张有刻度的图，也不要用看起来可点、实际不可点的元素。

## 数据形状

`GET /api/dashboard/overview`（`server/internal/service/dashboard.go`）按登录用户聚合：

- `open_issues_by_project`：该用户的**全部项目**（`repository/dashboard.go` 从 `projects` 出发 `LEFT JOIN issues`），没有开启问题的项目计数为 `0`。所以**空数组 ⟺ 没有项目**，有项目时最低也会返回 `0` 行。
- `daily_resolved`：固定 30 条（含 0 值日期），按 `issue_internal_meta.completed_at` 分日、按项目聚合。近 30 天没有完成记录时 30 条全是 0；更早完成的问题不计入这个窗口。

## 空状态约定

- 图表判定为空时**不渲染坐标轴、网格、曲线与点**，只渲染一处居中的次要文字（`ChartEmptyState`）。空状态不叠在图上，也不伪造数据点（旧实现曾塞一行「暂无项目」，与服务端的 `0` 行叠成两套空状态）。
- 空状态可以带一个真实入口 `emptyAction`，由页面传入；入口用 `Button render={<Link/>}`（如「去创建项目」→ `/projects`），不要用带边框的虚线胶囊伪装成按钮。
- 柱状图只在 `points.length === 0` 时算空：有项目但开启问题都清零时保留项目行和 `0`，读者仍能看到项目本身。值为 0 的行只画空轨道，不画填充段（短灰条会被误读成「有少量进度」）。
- 面积图在 `points.length === 0` 或窗口内最大值 `0` 时算空。
- 概览请求失败（`isError`）时不要把「没有数据」当成「没有项目」：页面顶部显示可重试的错误条，图表位置只显示「数据加载失败」，不显示空状态文案与「去创建项目」入口，KPI 显示 `—`。
- 卡片右上角的「日均 x.x」读数与趋势图标只在近 30 天有已解决数据时显示；空数据时整段隐藏（底部「日均解决」统计条仍显示 `0.0`），避免在空状态下暗示「在变差」。
- 趋势方向只拿**最近 7 天**与**上一个 7 天**比较：多于前一周 → 上升（绿）、少于 → 下降（橙）、相等 → 持平（灰）、两周都为 0 → 不判定、不显示图标。没有上一周期数据时不要下结论。
- 日均大于 0 且小于 `0.1` 时显示 `<0.1`（顶部读数与底部「日均解决」一致）；日均等于 0（窗口内没有已解决记录）时仍显示 `0.0`。直接 `toFixed(1)` 会把 1 条/30 天渲染成 `0.0`，看起来像没有数据。

## 纵轴刻度

取整阶梯：最大值不超过 2 时只分两档（`tickIntervals = 2`），其余分四档；`tickStep = max(ceil(maxTotal / tickIntervals), 1)`、`chartMax = tickStep * tickIntervals`。于是最大值为 1/2 时刻度是 `0/1/2`（峰值至少占图高一半），最大值 5/7 时是 `0/2/4/6/8`，最大值 1000 时是 `0/250/500/750/1000`。直接用 `max(maxTotal, 1)` 会在最大值很小时产生 `1、1、1、0、0` 这种重复刻度，也会让峰值只占四分之一高。刻度文字用 `text-[11px]` 与 `fill-muted-foreground`。

横轴日期均匀取最多 7 个刻度（含首尾）：按 stride 取点再强塞最后一个点，会在某些数据长度（例如 27 个点）让末尾两个 `MM-DD` 相距约 17px 而叠印；改用 `Math.round(last * i / (count - 1))` 均分后再去重。

图表的坐标系用**实测宽度**（`ResizeObserver` 取容器宽度，`viewBox` 与该宽度一致，1:1 像素）。不要改回固定 `720x220` 的 viewBox：那会把整个图（包括坐标轴文字）等比缩小，纵轴数字实际只剩 ~8.7px，横轴日期与数据点也会错位。横轴日期直接画在 SVG 内、和数据点共用同一套 x 坐标，所以「最后一个日期」永远落在最后一个点正下方。
